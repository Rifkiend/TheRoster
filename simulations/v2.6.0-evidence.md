## Hasil per fitur

### 1. Fan-out runbook + `fanout_group` — LOLOS (§A, 43 langkah)

- `fanout.py create --max-members 1` DITOLAK (N harus 2–8).
- Grup t-101 (max 3): 3 member (assistant / teammate-1 / owner), masing-masing claim + worktree sendiri (`../wt-101-a/b/c`, branch `wt/t-101-*`), masing-masing menulis `src/checkout.py` yang berbeda di worktree-nya.
- Klaim sibling tanpa worktree pada file yang sama DITOLAK ("someone else is already working on this") — tidak ada pengecualian khusus untuk member fan-out; aturan konflik v2.3 berlaku penuh.
- Member ke-4 DITOLAK ("already has 3 member(s)").
- `decide` dengan winner bukan member DITOLAK; decide selagi ada member aktif DITOLAK; decide dengan winner ber-receipt `failed` DITOLAK; decide oleh owner winner DITOLAK.
- Decide yang benar (winner t-101-a, oleh owner): loser dilepas dengan `released_by: "fanout:t-101-a"`, satu event `claim_released` per loser; validate LOLOS (composite actor `fanout:` dilewati signature check seperti `flags:`/`cancel:`, commit diikat decider lewat `decided_by` di record grup).
- `cancel` grup t-102: member aktif dilepas `released_by: "fanout-cancel:owner"`; add ke grup yang sudah decided DITOLAK.
- `compare` scorecard: status live + outcome receipt + diffstat vs base_commit (atau "branch not on this machine"); exit 0 selalu.

### 2. Decision gates `team/gates/` — LOLOS (§B, 43 langkah)

- Gate g-201 (blokir PRD prd-001) menolak klaim t-201 di claim time ("decision gate g-201 is OPEN") — sebelum ada pekerjaan terbuang.
- Gate untuk subject yang tidak ada DITOLAK (kecuali gate klaim, boleh dibuat sebelum klaimnya).
- Resolve oleh pemilik subject DITOLAK ("differ from the subject's owner"); resolve oleh teammate-1 LOLOS.
- Mid-work gate g-202 (dibuat setelah klaim ada): `claim.py check` GAGAL dan `validate.py` GAGAL dengan bentuk yang sama seperti fitur yang dibatalkan.
- Waive oleh agent DITOLAK ("is not a human roster member"); waive oleh owner (human) LOLOS; setelah waive, check + validate LOLOS.
- Resolve dengan `--review r-201` (approve, subject sama) LOLOS; resolve dengan `--review r-202` (request-changes) DITOLAK ("only an approve review").
- Semua gate di akhir §B resolved/waived; validate LOLOS.

### 3. Typed completion receipts — LOLOS (§C, 30 langkah)

- `claim.py done` tanpa `--outcome` DITOLAK oleh argparse ("required: --outcome") — no silent done.
- Done oleh agent lain (assistant-2, bukan owner, bukan human) DITOLAK ("is not the claim owner").
- Done oleh owner (human) tanpa `--key` DITOLAK ("must sign the receipt") — require_signatures on.
- Done oleh owner dengan `--key` LOLOS: receipt bertanda tangan (sig string `-----BEGIN SSH SIGNATURE-----`), klaim mencatat `done_by=owner` — tanpa field ini, push akan gagal one-owner rule.
- Receipt `failed` (t-303): klaim tetap done, PRD prd-001 MASIH `in_progress`, fitur terkait tidak naik ke stable.
- Receipt palsu (claim_seq diganti 999): `receipts.py check` GAGAL ("does not match claim"); pulihkan → LOLOS.
- Receipt bertanda tangan yang summary-nya diubah: check GAGAL ("invalid sig"); pulihkan → LOLOS.

### 4. Formal review record `team/reviews/` — LOLOS (§D, 20 langkah)

- PRD prd-001 `--to done` DITOLAK selagi review terakhir r-202 request-changes ("request-changes").
- Review r-203 (approve, teammate-1, lebih baru) membersihkan r-202; PRD `--to done` LOLOS setelahnya.
- Review oleh pemilik subject DITOLAK ("owns the reviewed claim"); review pada task yang tidak ada DITOLAK; anotasi baris 0 DITOLAK ("must be a positive number").
- Delivery mailbox: baris berisi id review + kata verdict `accepted` SAJA — teks bebas reviewer ("Timeout case") tidak bocor ke mailbox; validate LOLOS (pola imperatif tidak terpicu).
- Klaim follow-up t-305 dengan `--review r-202` (request-changes) LOLOS; klaim dengan `--review r-203` (approve) DITOLAK ("only a request-changes review").

## Bug yang ditemukan pengujian — semua diperbaiki + diverifikasi ulang

Empat bug ditemukan smoke test (bukan oleh s11), dua celah desain ditemukan saat menulis s11, satu celah parser ditemukan run pertama s11:

1. **Append `.jsonl` tidak aman terhadap newline** — file mailbox starter berakhir tanpa newline, sehingga delivery review pertama menempel di baris 1 dan merusaknya (validate: "assistant.jsonl:1 is not valid JSON"). Perbaikan: `team_common.append_jsonl()` / `append_text_lines()` (tulis newline pemisah dulu bila file tidak kosong dan tidak diakhiri newline); dipakai `append_event`, `mailbox.py sign`, delivery review, `archive_events.py`; file starter sendiri kini diakhiri `\n`.
2. **Signature check bersama tidak cocok** — `check_gates()`/`check_reviews()` hanya menerima `(dir, roster_path=None)` dan `check_receipts()` menerima `cfg`, bukan `team_dir`. Empat pemanggilan di `validate.py` diperbaiki agar cocok.
3. **Bug tuple di `cmd_done`** — `tc.ssh_sign` mengembalikan `(sig, error)`, tapi `cmd_done` menyimpan tuple mentah (bukan string) dan memanggil `verify_receipt_signature` dengan urutan argumen salah (sig harus TERAKHIR) DAN memperlakukan tuple `(ok, err)` sebagai bool (selalu truthy — "verified BEFORE writing" tidak pernah bisa gagal). Diperbaiki: unpack kedua tuple, urutan benar. Diverifikasi di fixture bertanda tangan: sig kunci salah kini GAGAL di done time, kunci benar LOLOS, sig tersimpan sebagai string, validate OK. `claim.py` satu-satunya pemanggil `ssh_sign`.
4. **Atribusi `done_by` + actor komposit `fanout:`** — klaim mendapat field `done_by` (diisi `cmd_done`); `validate.py` mengatribusikan klaim done ke filer, bukan owner (bentuk yang sama seperti `released_by`/`stalled_by`) — kalau tidak, manusia yang mengajukan receipt atas nama agent tidak pernah bisa push klaim + receipt bersama. `released_by` `fanout:<winner>` / `fanout-cancel:<by>` dilewati signature check seperti `flags:`/`cancel:`; commit diikat decider lewat `decided_by`/`cancelled_by` di record grup.
5. **Parser `reviews.py` tidak punya `--annotations`** — flag didefinisikan sebagai `--annotation` (tunggal) sementara design doc, SKILL.md, dan s11 memakai `--annotations` (jamak). Diperbaiki: flag diganti `--annotations` + `args.annotations` + docstring. Ditemukan run pertama s11 (D6: "unrecognized arguments: --annotations").
6. **Skenario s11, tiga perbaikan (bukan bug kode):** needle B14 salah kapital ("must be a human" vs pesan kode "is not a human roster member"); reviewer human butuh `--key` saat require_signatures on (B24/B33/D2 — tanpanya review tidak pernah dibuat dan g-203 tidak pernah ter-resolve, berantai ke C26/D1); aturan one-owner berlaku untuk SELURUH push range — s11 kini push di antara unit aktor yang berbeda (seperti s9/s10); klaim follow-up t-305 harus menunggu t-201 done dulu karena menyentuh file yang sama (satu file tidak boleh diklaim dua kali selagi aktif, walau owner-nya sama).

Run pertama s11: 18 langkah gagal, semua berantai dari 3 penyebab di atas (poin 5–6). Run kedua: 5 gagal. Run ketiga: **149/149**. Suite penuh setelahnya: **424/424**.

## Yang TIDAK diuji — jujur

- **Fan-out dengan N=8 penuh** — hanya 3 member dipakai; penolakan member ke-4 menguji logika cap, bukan 8 member sekaligus.
- **Merge pemenang** — `compare` adalah scorecard; keputusan merge tetap manusia, by design tidak diotomasi.
- **Clock-skew pada record baru** — gate jam miring v2.5 hanya memeriksa klaim (`started_at`/`heartbeat` dari masa depan); `created_at` fan-out/gate/receipt/review dari masa depan belum diuji.
- **Multi-machine untuk record baru** — s11 single-clone + bare remote. `sync_check.py` sengaja tidak disentuh; `validate.py` membaca record baru setelah fetch+rebase, tapi jalur fetch+rebase antar-clone untuk keempat tipe record ini tidak dijalankan.
- **Doctor check 11 saat script hilang** — jalur warn (script tidak ada) tidak dijalankan; semua script ada di fixture.
- **Urutan validasi anotasi vs `--key`** — D6 melewati `--key` agar kegagalan dijamin dari anotasi; urutan internal (anotasi dicek sebelum key) didokumentasikan, tidak diuji tanpa `--key`.
- **Biaya token fan-out** — ×N didokumentasikan di design doc dan SKILL.md, tidak diukur dengan run multi-agent sungguhan.
- **Server premium** — TIDAK dibangun (di luar arah; butuh validasi 5–10 pengguna dulu).
- **Release GitHub (tag v2.6.0)** — BUKAN bagian tugas ini; jalur browser, parent yang lanjutkan.
