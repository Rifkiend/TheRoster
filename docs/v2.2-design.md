# v2.2 design — PRD layer, cancellation, contracts + dependencies

## Why

Three gaps from real use:

1. **No PRD layer.** Tasks were born from claims made ad hoc — nothing
   recorded *why* the work exists. A claim on a feature nobody
   decided to build is indistinguishable from a claim on a decided one.
2. **No cancellation.** A feature killed mid-flight had no status of
   its own. Its claim could sit active, and the next AI could pick
   the work back up without knowing it was deliberately killed.
3. **No contract protection.** A function or database schema shared
   between two developers is an interface, but the registry treated
   it like any other entry point. B could change A's entry and the
   only signal was a blob-sha mismatch at push time — with no record
   of who depends on it.

## Design principle

Every new power gets a named failure mode, a mitigation, and a
control knob. Nothing in v2.2 is silent, and nothing is mandatory
by default — teams opt in to the strictness they can afford.

| Shortcoming | Mitigation | Control |
|---|---|---|
| PRD goes stale (marked done, code is not) | validate.py FAILs a done item whose features are missing or not stable/cancelled | `prd_required` (default off) — claims must name a PRD item |
| PRD item points at a feature that does not exist yet | Allowed while planned/in_progress (it is future work); the done-gate in `prd.py status --to done` and validate.py enforce reality at the moment it is marked done | — |
| Feature cancelled mid-work; the worker keeps working | Cancel releases overlapping active claims **in the same push** (recorded as a release, exempt from one-owner); sync_check FAILs when the remote cancelled a feature your local active claim touches | — |
| Cancelled feature rebuilt by accident | Cancelled features stay in the registry, searchable, ranked last, excluded from reuse; entry verification is skipped for them (dead history, not live code) | — |
| Contract changed silently by B | Contract entry changes need `--contract-change` **plus** `--bump major`; the blob-sha check still catches any entry drift; the entry file should carry a `# roster-contract: <id>` marker (warned, not failed) | the `contract` flag itself |
| Dependents break silently when a contract bumps major | `depends_on` records the version verified against; validate.py warns "needs reverify" until `features.py reverify` refreshes it | `strict_deps` (default off) — warn becomes FAIL |
| New checks slow the push / false positives | All new validations are warn-first except genuine contradictions (done item with unstable features, claim on a cancelled/done item, dependency on an unregistered feature) | both knobs above |
| PRD items reference features by id only — deleting a feature breaks the link | Features are never deleted (only deprecated/cancelled), so a PRD link can only go stale by a missing registration, which the done-gate catches | — |

## What v2.2 does NOT fix (still honest)

- **No real-time presence.** A cancellation is visible at the next
  fetch, not instantly. The window is bounded by sync_check (it
  runs right before the push), not eliminated.
- **The PRD is still a file.** There is no live link to the PRD
  document itself — `source` is a pointer (e.g. `docs/prd.md#login`),
  and nothing checks the document still says the same thing.
- **No atomic claims.** The search → claim → push → fetch race
  remains; `claim_seq` fences it, a server would eliminate it.
  (Same honest limit as v2.0 — see the research report.)

## Files

- New: `scripts/prd.py` (create/list/status/check), `references/prd.md`,
  `docs/v2.2-design.md` (this file).
- Extended: `scripts/claim.py` (`--prd`, `prd_item`), `scripts/features.py`
  (cancel, `--contract`, `--depends-on`, `--contract-change`),
  `scripts/validate.py` (PRD + dependency cross-checks),
  `scripts/sync_check.py` (remote-cancelled vs local claims),
  `scripts/rebuild_index.py` (prd section, contract flag, prd_item),
  `scripts/team_common.py` (`prd_required`, `strict_deps`, version).
- Version: 2.2.0 (minor, backward-compatible — old records are read
  as contract=false with no dependencies, and a team without team/prd/
  rebuilds with an empty prd list).
